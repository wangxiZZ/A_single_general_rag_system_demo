## 1. 目的与范围

**目的**

1. 证明题目 §4–§8 的功能要求在真实依赖（PostgreSQL + Milvus + Neo4j + 模型 API）下可用，
   不是"接口返回 200"式的假通过；
2. 用可复现的断言固化三类边界：知识库隔离、处理失败、删除后不可召回；
3. 给出一套"每次改动后 5 分钟能跑完"的门禁顺序，以及与交付验收一一对应的证据口径。

**范围**

| 纳入 | 说明 |
|---|---|
| REST `/api/*`、Web `/web/*` | 建库→上传→解析索引→检索→回答全链路 |
| 三路召回与融合 | `vector` / `keyword` / `graph` / `hybrid` / `hybrid_weighted` + `rerank` |
| 图谱闭环 | 抽取→校验→Neo4j 持久化→多跳展开→回原文子块 |
| 摄取 worker 与状态机 | `pending→parsing→chunked→indexing→ready/failed`、重试、reindex |
| 删除级联 | PG 行 / Milvus 实体 / Neo4j 节点与边 / 磁盘文件 |
| MCP stdio 三工具 + Skill | 只转发 REST；Skill 与源文件一致 |
| 评测脚本 | `scripts/bench/`、`scripts/graph_eval.py` |

**不纳入（题目明确不做，见 `design.md` §8 已知限制）**：OCR/扫描件识别、手写体、旧版 `.doc`、
复杂表格与公式还原、鉴权与多租户、流式输出。这些不做"失败"计，只验证**失败时错误可读**。

## 3. 测试环境

### 3.1 前置

| 项 | 要求 | 校验命令 |
|---|---|---|
| Docker Desktop | ≥ 8 GB 内存（Milvus 首次 60–90s） | `docker compose ps` 六个服务 `healthy` |
| Python | 3.12（`.python-version`） | `uv run python -V` |
| uv | 0.12+ | `uv --version` |
| 模型 Key | `LLM_API_KEY`、`EMBED_API_KEY`；图片用例需 `VLM_API_KEY` | `curl -s localhost:8000/readyz` |
| MCP extra | `uv sync --extra mcp`（e2e 必需） | `uv run python -c "import mcp"` |

### 3.2 启动与健康

```bash
cp .env.example .env          # 填三个 Key；Windows 本机 5432 被占用时设 PG_PORT=5433 并同步 PG_DSN
docker compose up -d --build
docker compose ps             # 等六个 healthy
uv run rag-kb migrate
curl -s localhost:8000/readyz | python -m json.tool
```

期望（本次实测基线）：

```json
{"ready": true, "checks": [
  {"name": "postgres", "ok": true, "required": true, "detail": "postgres 16.16"},
  {"name": "milvus",   "ok": true, "required": true, "detail": "milvus ok, collections=N"},
  {"name": "neo4j",    "ok": true, "required": true, "detail": "neo4j ok (RETURN 1)"},
  {"name": "model:llm", "ok": true, "required": false},
  {"name": "model:embedding", "ok": true, "required": false},
  {"name": "model:vlm", "ok": true, "required": false}]}
```

> `model:*` 三项 `required=false`：未配置不阻塞启动，但对应功能不可用，**不判失败**，只记录。

### 3.3 数据准备

```bash
uv run python scripts/make_fixtures.py          # tests/fixtures/documents/{sample.pdf,sample.docx,scanned.pdf}
uv run python scripts/make_graph_fixtures.py    # tests/fixtures/graph/{gold_doc.pdf,adversarial_doc.docx,gold.json}
uv run python scripts/load_demo.py              # 演示库：employee_handbook.pdf + product_guide.docx
```

### 3.4 环境隔离与重置（避免假通过/假失败）

- 每个集成用例使用**独立 `kb`（随机名）与独立 Milvus collection 名**（参考
  `tests/integration/test_isolation.py:126`），不共享库；
- Milvus 写删是最终一致的，本项目 collection 用 `Strong` 一致性，断言前无需 sleep；若换实现，
  必须先 `flush()`；
- 重跑前清理：`docker compose down -v`（清数据卷）或 `POST /api/kbs/{id}` 删除整库；
- **端口劫持坑**：本机已有 PostgreSQL 占 5432 时，容器端口映射"成功"但实际连本地实例
  （表现为 `role "rag" does not exist`）；用 `PG_PORT=5433`。

## 5. 用例矩阵

编号规则：`T-<域>-<序号>`；**断言必须落到数据与计数**，不接受"接口返回 200"。

### 5.1 环境与部署

| ID | 步骤 | 期望 |
|---|---|---|
| T-ENV-01 | `docker compose up -d --build` 后 `docker compose ps` | 六个服务全部 `healthy`，无 restart 循环 |
| T-ENV-02 | `GET /readyz`；停掉 neo4j 后再取 | 正常时 200 `ready=true`；依赖故障时 **503** 且该 check `ok=false`、`required=true` |
| T-ENV-03 | 不配 `EMBED_API_KEY` 启动 | 服务可启动，`model:embedding.ok=false`，`readyz` 仍 200（不阻塞） |
| T-ENV-04 | `uv run rag-kb migrate` 连续执行两次 | 第一次输出 `applied migrations`，第二次 `no pending migrations`（幂等） |

### 5.2 知识与文档管理（Web + REST）

| ID | 步骤 | 期望 |
|---|---|---|
| T-WEB-01 | `/web/kbs` 建库 | 303 跳转到详情页；列表出现该库 |
| T-WEB-02 | 详情页上传 `sample.pdf` | 303；文档行出现，状态经 `pending→parsing→chunked→indexing→ready` |
| T-WEB-03 | 状态轮询 | HTMX 每 2s 轮询；`ready/failed` 后该行不再带 `hx-get`（轮询自停） |
| T-WEB-04 | 上传 `scanned.pdf` | 行显示"失败"与可读错误（含「不支持扫描件 OCR」），出现"重试"按钮 |
| T-WEB-05 | 删除文档 / 删除整库 | 行消失 / 回到列表且库不存在 |
| T-WEB-06 | 静态资源 | `htmx.min.js` 由 `/static/` 本地提供；页面无 CDN 引用（grep `https://unpkg|jsdelivr`） |
| T-CRUD-01 | `POST /api/kbs` → `GET /api/kbs` → `GET /api/kbs/{id}` → `DELETE` | 201/200/200/204；删除后 404 |
| T-CRUD-02 | 同库重复上传同一文件 | **409**，响应体含 `existing_document_id`，且不产生第二个文档行 |
| T-CRUD-03 | 上传 `sample.docx`（文件名伪装 `.docx` 但内容非 ZIP） | **415**，不建行、不落盘 |
| T-CRUD-04 | 上传 > `MAX_UPLOAD_MB` 的文件 | **413**，不建行、不落盘、不入队 |
| T-CRUD-05 | `GET .../documents/{id}/chunks` | 返回 `level/kind/heading_path/page_no/page_to/bbox/char_start/char_end/token_count/meta/chunker_version` |
| T-CRUD-06 | `POST .../retry` 于 `ready` 文档 | **422**（只有 failed 可重试）；于 `failed` 文档 → 202 + `pending` |

### 5.3 解析与分块（R3/R4）

| ID | 步骤 | 期望 |
|---|---|---|
| T-PARSE-01 | 上传 `sample.pdf` 后查 chunks | 存在 `level=parent` 与 `level=child`；子块 `page_no`、`bbox` 非空；`char_end>=char_start`；父块 `token_count<=PARENT_MAX_TOKENS` |
| T-PARSE-02 | 上传 `sample.docx` 后查 chunks | `page_no/bbox` **均为 null**（不伪造页码）；`seq`、`char_*` 连续有效 |
| T-PARSE-03 | 标题层级 | `heading_path` 形如 `["1. 年假政策"]`，子块内容以标题前缀开头 |
| T-PARSE-04 | 上传 `scanned.pdf` | 文档 `failed`，`error` 含「不支持扫描件 OCR」；`chunk`/`doc_image` 计数为 0 |
| T-IMG-01 | 含图 PDF 的 chunks | 存在 `kind=image` 且 `image_id != null`、`page_no` 有值；`doc_image` 行 `(doc_id, seq)` 唯一 |
| T-IMG-02 | 含图 docx 的 chunks | `kind=image` 存在，`page_no/bbox` 为 null，`seq` 表示阅读顺序 |
| T-IMG-03 | 检索图片块 | 图片块可被 `vector`/`keyword` 命中；命中项应能取到原图（`image_url`）与定位信息 |

### 5.4 三路召回与融合（R5/R7/R9）

| ID | 步骤 | 期望 |
|---|---|---|
| T-SEARCH-01 | `mode=vector` 查「年假有几天」 | 非空；`channels==["vector"]`；`doc_name/page_no/heading_path/snippet` 有值 |
| T-SEARCH-02 | `mode=keyword` 查短术语「年假」「报销」「部署方式」 | 非空；命中块内容含该术语；`channels==["keyword"]` |
| T-SEARCH-03 | `mode=graph` 查实体关系问题（如「哪个部门负责上线审批」） | 非空；`level=child`；`debug` 含 `hops/seed_ids` |
| T-SEARCH-04 | `mode=hybrid` | 非空；`channels` 至少两项（多路命中合并）；按 `chunk_id` 去重（无重复 id） |
| T-SEARCH-05 | `mode=hybrid_weighted` | 非空；顺序可与 RRF 不同（对照实验分支可用） |
| T-SEARCH-06 | RRF 语义 | 同一 `chunk_id` 只出现一次，`channels` 合并顺序稳定；`score` 随排名单调不增 |
| T-SEARCH-07 | `rerank=true`（配置了重排端点） | 只对前 30 候选重排；`debug.rerank_rank` 出现；未配置端点时 **503** 且错误可读 |
| T-SEARCH-08 | 返回结构 | 五模式均含 `chunk_id/doc_id/doc_name/level/page_no/heading_path/snippet/score/channels/debug`；`top_k` 生效（`1≤top_k≤50`） |
| T-SEARCH-09 | 空/无意义查询（如 `！！！`） | 200 且 `[]`（清洗后空 token 直接返回空，不抛 SQL 错误） |
| T-SEARCH-10 | `mode` 非法值 | **422**（Pydantic 枚举校验） |

## 6. 三类边界用例（R12，题目点名）

### 6.1 知识库隔离 `T-ISO-*`

| ID | 步骤 | 断言（全部为计数/ID 比对） |
|---|---|---|
| T-ISO-01 | A 库存「年假政策」（PDF），B 库存同名不同内容 | 用 A 库关键词查 B：`vector/keyword/graph/hybrid` 四模式均 `== []`；结果里不出现 A 的 `doc_id` |
| T-ISO-02 | A/B 各建同名文档、同名实体 | `graph` 通道在 A 只返回 A 的 chunk；Neo4j 路径不跨库（`Entity.kb_id` 唯一约束生效） |
| T-ISO-03 | 直接用端口层验证 | `vector.count(kb_b)` 只含 B；`lexical.count(kb_b)` 只含 B；`graph.count(kb_b)` 只含 B |

### 6.2 处理失败 `T-FAIL-*`

| ID | 步骤 | 断言 |
|---|---|---|
| T-FAIL-01 | 上传超限文件 | **413**；`document` 行数不增；`data/uploads` 无新目录 |

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Milvus 首次启动慢 / 内存不足 | G2 直接失败 | `start_period=90s`；内存 ≥ 8 GB；`docker compose ps` 等 healthy 再跑 |
| Milvus 最终一致性导致"删除后仍命中" | 假失败 | collection 固定 `Strong`；换实现时断言前 `flush()` |

## 13. 已知不判失败的项

- 扫描件/OCR、手写、旧版 `.doc`：**明确失败且错误可读**即通过；
- 复杂表格、公式、多栏版式还原质量；
- docx 无页码/bbo​x：只要不伪造即通过；
- 复杂中文新词/专有名词分词不准（但 §9 R-01 的"整词被合并成伪复合词导致 0 命中"属于缺陷，需修）；
- 无鉴权、无流式输出（本阶段范围外）。
