## 1. 决策冻结（DOC-00）

下表是本轮文档修订的**唯一事实来源**。后续所有文档修改都以此为准；若某项需要变更，先改
本表并记录原因，再重跑受影响的任务。

| ID | 决策点 | 采用值 |
|---|---|---|
| D1 | 文档状态机 | `pending → parsing → chunked → indexing → ready`，任一步失败进 `failed`；`failed` 可重试回 `pending`（`attempts+1`）。**`ready` 仅表示向量/词法/图谱三路索引全部完成**，不是"解析完就算 ready" |
| D2 | 检索单元 | 检索命中与 `/search` 返回**子块**；父块只用于回答阶段的上下文回填；图谱关系边的 `chunk_id` 必须指向可检索的子块，按 `evidence_span` 的字符区间映射，映射失败才退回父块并在结果中标记 `level=parent` |
| D3 | chunk 模型 | 统一字段：`id, kb_id, doc_id, parent_id, level(parent\|child), kind(text\|image\|table), content, heading_path, page_no(nullable), page_to(nullable), bbox(nullable), char_start, char_end, token_count, image_id(nullable), chunker_version`；`unique(doc_id, seq)`；只有 `level=child` 进向量/词法索引 |
| D3a | chunk_id | `sha256(f"{doc_sha256}:{seq}:{chunker_version}")[:32]`，确定性生成，保证 upsert 幂等与评测金标可复现 |
| D4 | 定位口径 | PDF：`page_no + bbox + char_start/char_end` 必填；docx：`char_start/char_end + seq` 必填，`page_no/bbox` 允许为 null（不渲染就没有页码与坐标）。AGENTS 的"前四项"约束按格式能力区分表述 |
| D5 | 实体存储 | **以 Neo4j 为唯一实体/关系存储**，删除 PostgreSQL 的 `entity` 与 `chunk_entity` 两张表；查询期种子实体链接、多跳展开、打分都通过 `GraphStore` 端口完成 |
| D6 | 端口契约 | 新增 `MetadataRepository`（KB/Document/Chunk/IngestJob/QueryLog 的读写，含 `claim_job`）、`Reranker`、`VLM`。所有 I/O 端口方法为 `async def`；同步 SDK（psycopg/pymilvus/neo4j）的适配器内部用 `anyio.to_thread.run_sync` 包装；`Parser.parse()` 为同步 CPU 密集方法，由 worker 放进线程池调用 |
| D7 | 配置契约 | 容器不读 `.env`，compose 的 `environment` 是唯一透传通道；`Settings` 的每个字段必须在 compose 中出现（或明确标注"仅宿主机直跑"）。新增 `RERANK_BASE_URL/RERANK_MODEL/RERANK_API_KEY/RERANK_TIMEOUT_S`、`QA_MAX_CONTEXT_TOKENS`、`GRAPH_NEIGHBOR_LIMIT`、`EMBED_MAX_CONCURRENCY`。增加 `tests/unit/test_config_compose_sync.py` 做机器校验 |
| D8 | 重排策略 | 默认 `rerank=off`；开启时默认走 cross-encoder（`bge-reranker-v2-m3`）；LLM listwise 是**显式 opt-in**（`rerank=llm`），不属于检索默认路径，不违反 AGENTS"查询期不得隐式触发 LLM" |
| D9 | 失败口径 | 超过 `MAX_UPLOAD_MB` → 上传接口返回 **413 且不建 document 行**；损坏文件/无文本 PDF/解析异常/缺少 `EMBED_API_KEY` → `status=failed`、错误可读、**写索引前失败**、可重试；删除与摄取并发用 tombstone 中止并清理 |
| D10 | MCP 与 Skill | `mcp` 作为可选依赖（`mcp[cli]`），提供 `rag-kb-mcp` 入口；Skill 安装到 `~/.claude/skills/rag-kb/` 或项目 `.claude/skills/rag-kb/`，仓库内 `skills/rag-kb/` 只是源文件 |
| D11 | 检索实现约束 | Milvus 每次检索必须带 `kb_id` 等值过滤，集成断言前 `flush()` 或使用 Strong 一致性；PG 查询侧 token 需清洗后拼 `to_tsquery`，并维护中文停用词表；图谱查询所有节点带 `{kb_id:$kb}`，每个种子邻居数受 `GRAPH_NEIGHBOR_LIMIT` 限制；边权默认 1.0，路径分 `Π edge_weight × 1/(1+hops)`，块分取到该块路径分之和 |
| D12 | 评测口径 | 金标用 `(doc_id, page_no, char_start, char_end)`（或页面级命中）而非 chunk id；样本 20–30 条；维度只保留 `mode × rerank`，**去掉 chunk_size 维度**；M7 开始前冻结 chunking 规则与 chunk_id 生成规则 |

### DOC-07 修正图谱闭环（`实施计划.md` §5.3）

**目标文件**：`docs/实施计划.md`

1. **抽取范围**：只对 `level=child AND kind=text` 的块抽取；图片块的 caption 不参与
   span 校验，避免"span 找不到"把图片实体全部丢弃。
2. **span 校验**：先原文精确匹配，失败再做空白归一匹配；仍失败丢弃。
3. **证据映射**：`evidence_span` 落在哪个子块，就把边的 `chunk_id` 指向该子块；
   跨子块时取覆盖字符最多的子块；映射失败退回父块并标 `level=parent`。
4. **检索闭环**：
   - 所有节点带 `{kb_id:$kb}`；
   - 每个种子邻居数受 `GRAPH_NEIGHBOR_LIMIT` 限制；
